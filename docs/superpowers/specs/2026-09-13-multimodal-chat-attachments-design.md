# 深度思考、视觉模型与会话附件需求设计

状态：用户已确认，已实施。基于 5303c5e；具体实现边界与验证结果见 `docs/多模态聊天与会话附件.md`。

## 目标

让用户逐次选择是否深度思考、是否使用视觉能力，并在聊天输入区附加图片、TXT、MD、PDF、DOCX。文本/OCR 处理复用现有入库组件，附件可支持后续追问，也可显式保存到知识库。保留现有鉴权、持久任务、流式输出和引用能力。

## 方案与默认决策

推荐“会话私有附件 + 共用处理组件 + 按需保存到知识库”。直接将所有聊天附件入库虽实现简单，但会改变知识库内容与共享范围；只在请求内临时解析虽简单，但不支持恢复、历史附件及后续追问。本轮不采用这两种方式。

附件默认仅归属当前会话，随会话保留，删除会话后不可访问；原件由现有带宽限期的维护机制清理。用户显式保存到某知识库后，库内副本按知识库成员权限管理，不随会话删除。

## 用户交互

输入区提供三个独立控制：模型选择、深度思考开关、视觉理解开关。界面展示实际模型名称和可用能力。模型列表由服务端配置，至少支持文本模型和视觉模型配置项，也允许同一个模型兼具两种能力。

- 深度思考默认关闭，但用户可随时开启；选择作为默认偏好保存，每条已发送消息记录当时选择，不受后续切换影响。
- 视觉理解默认开启；只有已配置且可使用视觉模型时才能启用。开启时使用所选视觉模型处理图片；关闭或无视觉能力时使用 OCR。切换视觉开关若需要切换实际模型，界面同时显示将使用的模型，不能暗中切换。
- 深度思考不受支持时禁用该选项并说明原因，不能显示开启却静默忽略。快速/深度模式采用服务端模型适配配置；无法明确关闭推理的模型应展示“供应商默认”，不能冒充快速模式。
- 提供选择文件、拖拽文件、粘贴图片。支持 PNG/JPEG/WEBP/BMP、TXT/MD、PDF、DOCX；每次最多 5 个附件，每个最多 20 MB，整次上传最多 50 MB。
- 发送前显示图片缩略图或文件卡片，以及上传中、排队中、解析中、就绪、失败状态。可移除附件和重试失败任务。默认等待所选附件就绪后发送；失败附件不能被悄悄略过。
- 允许只发附件；无文字时展示并使用默认任务“请概述这些附件的主要内容”。
- 历史消息展示附件卡片、当次模型和思考/视觉选项。后续追问可引用同会话已就绪附件；发送区展示当前选用范围，避免隐式携带所有历史图片增加延迟。
- 用户可显式将附件保存到有编辑权限的知识库；操作前显示目标库与共享范围。重复点击同一附件到同一目标库不产生重复入库任务。

## 模型能力与请求边界

新增服务端模型配置与能力接口，包含公开的模型 ID、名称、视觉能力、推理控制能力、上下文预算和每次图片限制。前端不持有 API Key，不允许请求任意 base URL、供应商参数或本地文件路径。

ChatReq 增加 model_id、thinking_mode、vision_enabled、attachment_ids。服务端校验模型和选项组合，并在每次请求构造独立模型调用参数；不得修改进程级全局开关或共享对象中的可变模型状态，以免并发用户相互影响。

深度思考开关用于最终回答。查询分类、检索改写、附件预处理及记忆更新采用独立的低延迟配置，避免一次提问产生多次深度推理。深度模式需要相应的输出预算，并记录实际使用模式；快速模式继续以接近直接 LLM 调用的耗时为目标。

只显示“深度思考中”等状态、首字和总耗时；不回显、保存或发送模型隐藏推理正文作为聊天历史。

## 附件处理路径

| 输入 | 视觉开启且模型支持 | 视觉关闭或模型不支持 |
| --- | --- | --- |
| 图片 | 校验和规范化图像，在最终模型请求中传 image 内容 | OCR 提取文字，作为附件资料输入 |
| TXT / MD | 文本解析 | 文本解析 |
| DOCX | 段落和表格解析 | 段落和表格解析 |
| PDF | 文本层解析；扫描页 OCR | 文本层解析；扫描页 OCR |

本轮 PDF/DOCX 走文档解析，不假设所有供应商都能直接接收这些文件。图片视觉输入与文档文本解析分开。PDF 中纯图表的完整视觉理解不在这条默认解析路径中；需要看图表时可附加对应截图，界面说明此边界。

图片直接送模型前检查真实格式、尺寸和像素数量，限制解码资源；生成适配模型限制的派生图像，保留原件。只向供应商发送用户选用的图片，不发送可长期访问的公开附件 URL。OCR 无有效文字时明确说明无法仅凭文字解析理解图片，不能假装已看图。

视觉调用不支持/失败时返回可操作提示，允许用户选择 OCR 重试或换模型；不能静默把失败的看图回答降级成猜测。模型能力声明由配置负责，真实兼容性通过受控测试图片验证。

## 复用与持久化

抽取共享的文件校验、原件存储、PDF/DOCX/文本解析、OCR、带位置切块和向量化服务。现有知识库入库和新会话附件调用这些组件，复用租约、续租、重试和领取令牌隔离机制。

新增会话附件资源与解析结果记录，明确 owner、session_id、状态、文件位置、页码/块定位和内容版本。附件与知识库文档保留各自权限，不能通过建立一个所有人可访问的临时知识库绕过鉴权。任务层支持不同任务类型，迁移保持原入库任务兼容。

短文档按上下文预算直接进入附件资料；长文档问答使用附件范围内检索。用户要求全文总结时分段汇总并合并，记录覆盖范围和有界处理预算；不能只检索少数片段却声称总结完整全文。超出本轮预算时明确提示范围或要求缩小附件选择。

附件是用户明确提供的依据：仅有附件也能进入有依据的回答路径，不受“知识库没有文档”拒答逻辑阻断。与已选知识库共同使用时，对两种来源统一编号并注明来源类型。

解析内容、OCR 文本和附件内指令均为不可信资料，不提升为系统指令。文本引用可定位原附件页码/分块；视觉引用定位图片本身，不编造 OCR 文本坐标或证据。

保存到知识库时复用相同解析版本和配置的结果，必要时执行知识库向量化；原件、引用和删除语义各自独立，避免删除会话使知识库原件失效。组件代码复用不等于共享未经授权的数据。

## 权限、失败与清理

- 上传、预览、下载、解析状态、取消/重试、问答引用、保存到知识库均校验用户与会话所有权。
- 请求不能引用其他会话附件 ID；会话删除后排队任务取消，过期 Worker 不得提交结果或复活附件。
- 临时上传未发送的附件使用明确过期策略：24 小时后可清理；已发送附件随会话保留。移除尚未发送附件可标记取消，清理由维护机制执行。
- 每次请求在附件选择、生成前及完成保存时检查状态和权限。已经发送的 token 无法撤回。
- 错误区分上传、解析/OCR、向量化、上下文预算和模型能力；保留安全阶段日志，不输出文件正文、密钥、Base64 图像或隐藏推理内容。
- 单个附件失败时，用户可以重试/移除；其他附件处理结果保留。

## 实施顺序

1. 模型配置和能力校验、逐请求深度/视觉选项、历史模式记录；保持无附件聊天可用。
2. 共享解析服务、附件表及版本化迁移、持久解析任务、权限和生命周期；保留旧入库兼容。
3. 附件问答与原生图片输入、上下文预算、长文档检索/分段总结、引用定位。
4. 前端选项、附件交互、历史回显和保存到知识库；普通与 SSE 路径一致。
5. 定向验证、部署配置与面试材料更新。

## 验收

- 相邻/并发请求分别启用和关闭深度思考，实际供应商参数正确且互不污染；模式不支持时明确拒绝。
- 视觉请求确实携带图像；文本模型只收到 OCR 文本；隐藏推理不出现在答案、日志、数据库历史中。
- 图片、TXT、PDF、DOCX 可上传，解析失败可重试，刷新和 Worker 重启后状态可恢复。
- 无知识库、有附件的提问正常回答；短文件完整使用、长文件不会越过预算或伪称全文覆盖。
- 两个用户及两个会话互不越权；删除竞争和重复保存不会造成残留可访问附件或重复入库。
- 附件可在历史中打开原件/引用位置；已保存到知识库的副本不依赖会话存活。
- 用生成的测试图片和合成文档验证真实视觉调用；不将用户现有私有附件自动外发作为开发测试。
- 只验证新增及受影响路径。分别报告快速/深度首字和总耗时、视觉与 OCR 路径、长文档处理覆盖，不重跑已通过的无关评测。
