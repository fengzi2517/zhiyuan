# RAG 稳定性与安全修复设计

## 背景

当前 RAG 应用的主流程已经完整，但代码审查和隔离复现确认了输入校验、状态机终止、联网策略、切块边界、PCA 小样本、前端 HTML 渲染、会话记忆一致性和启动迁移安全等问题。本轮目标是让现有单机 POC 在异常输入和边界数据下可预测地工作，并建立最小自动化回归基线。

## 范围

本轮修复：

- 清洗聊天 Markdown 和向量 tooltip 中的不可信 HTML。
- 校验聊天请求参数，保证 LangGraph 所有失败路径有限终止。
- 让联网开关覆盖主动联网和兜底联网两条路径。
- 修复短文档、英文长句和无标点长文本的切块边界。
- 修复 PCA 的单样本、单主成分和零方差情况。
- 返回消息 ID，使新消息编辑可持久化；删除会话时同步删除记忆。
- 禁止应用启动时自动删除文档和向量，改为明确报错。
- 补充入库失败原因、基础日志、缺失依赖和关键测试。

本轮不引入认证、BM25、Celery、SSE、Alembic 全量迁移或推理服务拆分。这些需要单独设计和部署决策。

## 设计

后端请求模型使用 Pydantic 字段约束和去空格校验，在进入 LangGraph 前拒绝空问题、非法 top_k 和非法阈值。图路由统一读取 `web_enabled`；重排无结果时统一推进 `retries`，路由以明确的最大重试次数终止。

切块器继续保持现有标题感知结构，但英文句点加入句界识别；任何单句超过目标尺寸时使用带重叠的字符级保底切分。非空短文档保留为一个块。入库若解析或切块为空则进入 failed，并保存可供 UI 查看和重试的错误原因。

PCA 提取为可测试的纯函数。零样本返回空结果；单样本返回原点；仅一个主成分时补零；零方差时解释率返回零，禁止 NaN 进入 JSON。

消息写入返回数据库 ID，聊天响应将两个 ID 回传给前端。会话删除在一个事务中同时删除消息和长期记忆。向量维度不匹配时启动失败并给出迁移提示，不执行 DELETE。

前端安装 DOMPurify，对 Marked 输出清洗后再交给 `v-html`。ECharts tooltip 使用 HTML 转义函数处理来自文档的预览。聊天响应回填消息 ID。文档状态展示失败原因，并在轮询中检测全部完成后停止定时器。

## 错误处理与可观测性

入库捕获异常后记录异常类型和摘要，更新文档状态与 `error_message`，并使用标准 logger 记录堆栈。外部服务仍维持当前降级策略，但联网关闭时保证不调用 Tavily。敏感正文和 API Key 不写日志。

## 测试

后端使用 pytest 覆盖：请求校验、联网路由、图终止、切块边界、PCA 边界、短文档失败、会话删除和消息 ID。数据库相关逻辑用最小隔离替身测试事务行为，真实 PostgreSQL 集成测试留待后续环境化工作。

前端使用 Vitest 覆盖 HTML 清洗和 tooltip 转义；同时运行 Vite 生产构建。每项行为先写失败测试，再实现最小修复。

## 验收标准

- 恶意事件处理器和脚本不能进入渲染后的 HTML。
- 非法聊天参数返回 422，所有合法请求在有限图步骤内结束。
- `web_enabled=false` 时所有路径都不调用联网搜索。
- 短文本可检索，长英文或无标点文本不会产生超限块。
- PCA 对 0、1、相同向量数据返回合法 JSON。
- 新消息编辑可持久化，删除会话不保留长期记忆。
- 模型维度不匹配时不删除业务数据。
- 后端测试和前端测试、构建全部通过。
