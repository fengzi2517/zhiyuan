# 意图识别、流式回答与前端优化设计

## 目标

在保留“素笺墨线”浅色桌面风格的前提下，重构问答决策链、加入流式回答、建立可追溯引用，并优化智能问答、知识库管理、资料管理和设置页面。设计采用用户在视觉伴随页面选中的 B 方案：双栏主体加引用抽屉。

## 范围与约束

- 支持桌面端和常见窄屏桌面窗口，不单独适配手机端。
- 保持浅色主题，本轮不增加深色模式。
- 通用知识直接回答时不显示“未引用外部资料”等额外标签。
- 数据库变更只使用增加字段或新表的兼容迁移，不删除现有文档、向量、消息或记忆。
- 本轮实现意图识别、执行路由、引用、流式传输、历史持久化和四个现有页面的交互优化。
- BM25、身份认证、独立任务队列和多租户权限另行设计。

## 意图与路由分层

当前 `intent` 同时表达“用户想做什么”和“系统该走哪条路径”，导致所有非闲聊、非实时问题都被标为知识库问题。新设计把两者分开。

### 语义意图

- `chitchat`：问候、感谢、情绪交流、询问助手能力。
- `create`：写作、改写、总结、翻译、创意、生成代码或方案。
- `knowledge`：可由稳定知识回答的事实、解释、方法和专业问题。
- `current`：新闻、价格、现行政策、版本、人物职位等可能变化的信息。
- `mixed`：明确要求同时结合上传资料和最新外部信息。

### 执行路径

- `direct`：直接调用 LLM，适用于闲聊和创作。
- `kb`：检索知识库，适用于明确引用资料的问题，以及有可用知识库时的专业知识问题。
- `web`：联网搜索，适用于实时事实或知识库不足且需要事实核验的问题。
- `hybrid`：并行获取知识库与网络结果，等待两路完成后统一生成。

语义意图由结构化 LLM 分类，执行路径由确定性策略决定。策略输入包括语义意图、是否选择知识库、知识库是否有资料、联网开关和分类置信度。这样联网开关、资料选择和降级行为不依赖模型自由发挥。

### 决策顺序

1. 规范化问题并结合最近会话消解指代。
2. 确定性规则识别明确时效词、明确资料引用、创作指令和简单闲聊。
3. 对模糊问题调用 LLM，返回严格结构：`semantic_intent`、`query`、`needs_kb`、`needs_web`、`confidence`、`reason`。
4. 策略层校正模型结果：关闭联网时强制去除 web；明确选择资料时优先保留 kb；低置信度知识问题先检索知识库。
5. 执行 direct、kb、web 或 hybrid 路径。
6. 知识库无命中时只改写一次；仍无命中时，事实类问题在允许联网时转 web，创作类转 direct。

分类失败时返回 `knowledge`，策略层有知识库时选择 `kb`；没有可用资料且问题不具时效性时选择 direct，由模型直接回答。所有分支必须有显式终止条件。

## 引用与资料定位

检索结果统一转换为来源对象：

```text
id, type, title, excerpt, source_key,
document_id, chunk_id, page_start, page_end,
section, start_char, end_char, url, score
```

知识库 `source_key` 使用 chunk ID，网络来源使用规范化 URL。构建生成上下文前先按 `source_key` 去重并按相关性排序，随后分配 `[1]`、`[2]` 编号。同一来源在回答中重复出现时沿用同一编号。模型只能引用已分配编号；响应结束前删除不存在的编号，并只返回实际使用的来源。

解析与切块新增页码、章节、字符起止位置。PDF 保存原始文件并按页码打开；DOCX、TXT、Markdown 和图片在应用内打开提取文本，并滚动、高亮到命中片段。旧资料的新增元数据为空，仍可问答，但需要重新入库后才能精确定位。

## 流式协议

新增 `POST /chat/stream`，返回 Server-Sent Events。保留原 `/chat` 作为兼容接口，并复用同一问答服务。

事件类型：

- `status`：规范化、理解问题、检索知识库、精排、联网搜索、组织回答。
- `route`：语义意图、执行路径和简短原因。
- `token`：回答增量文本。
- `sources`：去重并编号后的来源列表。
- `trace`：可观察的阶段、结果数量和耗时，不展示隐藏推理过程。
- `done`：消息 ID、总耗时和最终元数据。
- `error`：用户可理解的失败阶段与可重试提示。

客户端断开时停止后续生成；保存完整回答后才发送 `done`。若流式连接中断，已落库的部分回答标记为 `interrupted`，历史中可识别并重新生成。

## 历史持久化

为助手消息兼容增加 `semantic_intent`、`route`、`sources`、`trace`、`elapsed_ms` 和 `status` 字段。旧消息字段为空时按普通历史消息显示。重新打开会话时恢复引用、处理轨迹和耗时。

消息编辑后将该会话长期记忆标为需要重建；编辑用户问题不自动覆盖原回答，界面提供“从此处重新生成”，由用户明确触发。

## 前端设计

### 智能问答：B 双栏加抽屉

左侧保留会话列表，主区域保留宽幅回答。原先折叠在气泡内部的来源改为右侧引用抽屉：点击正文编号或“引用来源”按钮打开；抽屉可以关闭或固定。点击知识库来源进入应用内资料查看器并定位命中位置，点击网络来源打开新标签页。

发送后立即显示一条紧凑处理轨迹，随 SSE 状态推进。首个 token 到达后切换为流式正文，完成后显示意图和耗时。界面名称从“AI 思维链”改为“处理过程”。

### 知识库管理

卡片强化资料数量、处理状态和最近更新时间；创建、删除和可视化操作使用一致的成功、失败与加载反馈。向量图保留为二级详情，不占据主列表。

### 资料管理

展示处理中、成功、失败数量，失败原因和重试入口。资料查看器支持来源定位与高亮。上传时显示文件级进度和目标知识库，避免误传到未分类区。

### 设置

按“检索”“联网与回答”“会话”分组；对阈值和 top_k 给出简短影响说明。流式回答默认开启；联网总开关继续拥有最高优先级。

## 后端边界

- 新增查询理解模块，输出经过 Pydantic 校验的结构化结果。
- 新增路由策略纯函数，禁止节点内部各自解释联网规则。
- 检索函数返回带元数据的对象，不再只返回文本字符串。
- 生成器接收已编号来源并提供同步与流式两种调用方式。
- API 层只负责校验、SSE 编码和响应，不承载业务路由。

## 错误处理

- 结构化分类失败时使用确定性默认值，并在 trace 标记降级。
- 网络搜索失败时保留知识库结果；仅 web 路径失败时给出可重试错误。
- 流式错误使用 `error` 事件结束，避免前端永久停留在加载状态。
- 引用定位失败时仍展示来源摘要和完整提取文本，不隐藏引用。
- 数据迁移只增加可空字段；任何不兼容 schema 都拒绝启动并给出显式迁移说明。

## 测试与验收

- 用固定问题表覆盖五类语义意图和四条执行路径，包括联网关闭、无资料、选中资料、混合问题和低置信度降级。
- 测试所有图分支有限结束，联网关闭时 Tavily 调用次数为零。
- 测试 SSE 事件顺序、异常结束、客户端断开和最终消息持久化。
- 测试来源去重、编号复用、非法引用剔除、历史恢复和资料定位。
- 前端测试流式状态、引用抽屉、会话恢复、失败重试和设置分组。
- 运行后端 pytest、前端 Vitest 和 Vite 生产构建。

验收时至少验证：创作请求不走知识库；实时问题可联网；明确资料问题优先知识库；混合问题同时使用两类来源；关闭联网后任何路径均不访问网络；同一来源重复引用编号一致；历史会话恢复引用与处理过程。
