# PostgreSQL 并发、鉴权与持久入库设计

状态：用户已确认，2026-09-12 完成实现与定向验证。目标是可部署的小团队 RAG 应用，保留现有检索、编排和评测能力。实际验证范围见 docs/落地验证记录.md。

## 当前依据

- 当前版本 bd7b623 已有会话事务锁、原子消息保存、记忆快照校验，但此前仅用 SQLite 验证相关逻辑。
- 所有业务接口目前开放，未选择知识库时检索全部数据，会话 ID 由客户端提供。
- 上传使用 BackgroundTasks，原文保存发生在后台，进程中断后没有可靠恢复入口；分块保存当前为追加操作。
- Docker 服务可用；检查时只有另一个项目的 PostgreSQL 容器运行，不将其用于测试或迁移。

## 方案选择

推荐 PostgreSQL 任务表、独立 Python Worker、服务端登录会话。与现有 SQLAlchemy/pgvector 栈一致，减少部署组件，允许多 Worker 安全竞争。

备选 Redis/Celery 提供更丰富任务生态，但增加 Redis 运维及数据库与队列双写问题；外部身份平台适合已有统一登录的企业，当前引入会增加演示部署依赖。本轮不选这两种方案。

## 1. 身份、权限和旧数据

- 管理员通过本地 CLI 初始化首个账户，密码交互输入或从受保护环境读取；不提供默认密码、不开放公开注册。管理员可创建、禁用账号及重置密码。
- 密码使用带随机盐的抗暴力破解哈希；登录错误统一返回，增加持久化、有时间上限的失败限流。日志不记录密码、Cookie 或完整登录载荷。
- 使用高熵随机会话令牌，数据库只保存摘要；Cookie 设置 HttpOnly、SameSite、有效期，生产环境强制 Secure。退出、禁用账户、重置密码使已有会话失效。
- 前端 Axios、SSE fetch、原文预览使用同一凭据机制；开发统一 hostname，CORS 使用明确来源列表并允许凭据，生产推荐同源反向代理。修改操作验证可信 Origin 和 CSRF token；登录也校验来源。
- 知识库具备 owner 和成员权限：reader 可检索与查看，editor 可上传与重试，owner 可管理成员和删除。管理员管理账户及显式管理资源，不默认浏览所有用户私人会话。
- 所有文档正文、原文、分块上下文、向量投影、任务状态与重试接口均校验所属知识库权限。无权资源返回一致的 404；未登录返回 401。
- 未选知识库的聊天只检索当前用户可读库，权限过滤进入 SQL，不能先全局检索再过滤；无可读库不能退回全库检索。检索请求显式传递权限上下文，禁止进程级可变用户状态。
- 新增会话所有权表；服务端创建或原子认领新会话，已有会话验证 owner。消息编辑、记忆、列表、删除和 SSE 与普通聊天执行相同检查。
- 权限变化影响后续请求；长生成在保存/完成前再次校验，已经发送给客户端的 token 无法撤回。该边界写入部署文档。
- 旧数据通过显式迁移命令分配给指定管理员，包括未分类文档和旧会话；迁移前展示数量，支持 dry-run、事务和重复执行。未认领数据默认不可见，不将其自动暴露给首次登录用户。
- 使用版本化迁移记录与迁移互斥锁，分离迁移和 Web 启动，避免多个实例同时执行 DDL。保留向量维度拒绝破坏性变更的保护。

## 2. 持久入库与一致性

- 上传先校验权限、扩展名和流式读取大小限制，再将原文写入共享持久目录的临时文件并原子重命名。文件成功持久化后，在一个数据库事务里创建 Document 和 IngestionJob，提交成功才返回 202、doc_id、job_id。
- 文件与数据库不具备跨系统原子事务：提交失败清理本次文件；崩溃产生的孤立文件由带宽限期、dry-run 的维护命令清理，禁止清理仍有引用的文件。
- Job 包含状态、尝试次数、最大次数、available_at、lease_until、claim_token、错误摘要、开始/结束/更新时间；Document 与 Job 状态同事务更新。针对可执行任务设置索引。
- 状态为 queued → running → succeeded；可重试失败进入 retry_wait，次数耗尽进入 failed；资源删除时取消任务。界面展示排队、执行、等待重试、成功和失败。
- Worker 使用短事务 SELECT FOR UPDATE SKIP LOCKED 抢占任务，数据库时间计算租约；模型加载、文件解析和向量计算均在事务外执行，不持有长期数据库锁。
- Worker 定期续租。过期任务可被其他 Worker 重新抢占，每次生成新的 claim_token。续租、失败处理和最终提交都必须匹配 token 与有效租约，旧 Worker 不能覆盖新 Worker 的结果。
- 成功提交同一事务完成全文写入、替换该文档旧 chunks、标记文档完成和任务成功；先检查分块数、向量数及向量维度，避免 zip 静默丢数据。重复执行不能增加重复 chunks。
- 采用至少一次执行和幂等提交，不承诺模型调用恰好一次。解析明确不可支持/无文本错误直接失败，暂时性失败按有上限的指数退避重试。错误详情写服务端日志，前端展示安全摘要。
- 删除知识库、取消任务和 Worker 提交遵循一致锁顺序及存在性检查，避免删除后重建文档。手动重试采用行锁且仅允许终态任务重试，重复点击不能创建多个活动任务。
- 独立命令启动 Worker，支持优雅退出；Web 重启不会丢任务。Web 与 Worker 共享上传卷与模型缓存，配置轮询间隔、租约、重试上限和 Worker 标识。

## 3. 真实 PostgreSQL 验证

- 集成测试放在独立目录，显式指定专用测试 DATABASE_URL，与当前默认禁止网络的单元测试隔离。
- 测试启动检查数据库名的测试前缀，使用独立测试容器/数据库；拒绝对业务库执行清理。测试并发使用独立连接、屏障和超时，避免仅靠 sleep 猜测竞争发生。
- 验证同一会话并发 save_exchange 不交叉写入；不同会话不被同一全局锁阻塞；事务失败不留下半条消息；旧记忆快照不能覆盖新消息或复活已删除会话。
- 验证多个 Worker 对同一任务只有一个有效 claim，锁住的任务不会阻塞其他任务；租约过期可恢复；旧 token 提交被拒；重复执行无重复 chunks；重试次数和删除竞争正确。
- 验证匿名访问、跨用户会话/消息/文档 ID、未指定库的跨库检索、原文下载、SSE、任务重试、会话过期及退出后访问等越权路径。
- 核心数据库并发测试使用确定性向量和伪模型，不依赖付费服务；另提供本地真实 embedding 的上传→入库→检索冒烟入口，报告中分别标明执行情况。
- 只运行新增和受影响测试；已通过且未受影响的评测、解析及前端用例不重复跑。

## 4. 部署与交付

- 提供 Web、Worker、pgvector 的部署配置、共享卷、环境变量示例和启动顺序；健康检查区分进程存活和数据库就绪，任务概览展示队列积压与过期执行。
- 补充数据库/原文备份恢复步骤、迁移步骤、首个账号初始化、失败任务恢复、停止 Worker 后恢复的演示流程。只暴露必要端口，不在示例中留下可用于生产的固定密码。
- 前端补齐登录/退出、当前身份、权限对应操作、任务进度和重试入口；沿用现有界面风格。
- 日志记录 request_id、user_id、job_id、worker_id、attempt 和状态转换；不记录凭据或全文资料。
- 实施顺序：数据库迁移和集成环境 → 身份及权限贯通 → 持久任务和 Worker → 前端与部署 → 定向验证及独立代码审查。

## 验收边界

两个账户互不可越权访问私有资源；两条独立数据库连接及多个 Worker 的竞争有真实 PostgreSQL 测试证据；Worker 中断后任务能恢复且旧 Worker 无法错误提交；前端可完成登录、上传、状态查看、失败重试及问答；原有数据通过显式迁移可继续使用。

本轮不包含 SSO、多机对象存储、分布式模型推理服务和高可用数据库集群。实施时已创建独立 PostgreSQL 18 + pgvector 测试容器并完成并发与权限验证；未修改业务数据库。
