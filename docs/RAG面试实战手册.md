# RAG 项目面试实战手册

以代码、提交和实验为依据，覆盖大模型应用/RAG 岗位常见追问。模型训练、CUDA 内核、强化学习等专项面试需要另行准备。

## 90 秒介绍

我围绕资料问答完善了“知源”RAG 项目。后端采用 FastAPI、BGE-M3 和 pgvector，前端是 Vue。入库支持多格式解析与扫描页 OCR，保留页码和章节等定位信息；检索采用向量召回、重排和一次查询改写。问题经结构化理解和确定性策略进入直接回答、知识库、网络或混合路径。

我重点完善了编排与异常工作流：普通与流式问答共用执行流程，资料不足明确说明限制，混合检索保留可用来源并提示缺失，回答带阶段耗时和引用定位。问答按事务成对保存，后台摘要通过事务内快照和条件写回避免历史编辑后旧记忆复活。

另外建立了固定合成语料的检索实验，区分召回、排序和无答案空检索指标。一次实验里重排减少了无答案问题返回资料的情况，但牺牲了一部分召回，因此不会仅凭“加了重排”宣称效果一定提升。

## 24 个核心追问

### 原理与选型

1. **为什么用 RAG？** 按问题检索外部资料后放入生成上下文，适合资料更新与来源核验。检索漏召回和模型误用证据仍会失败。追问：知识更新、长上下文和微调各解决什么问题？
2. **为什么不放全部资料？** 全量上下文涉及长度、成本和相关信息定位；检索集中上下文，也引入漏召回。追问：小资料集何时直接用长上下文？
3. **BGE-M3 怎么用？** 代码仅用 dense embedding，1024 维，不能声称已用 sparse 或 multi-vector。证据：app/embeddings.py。追问：模型更换为什么需要重编码文档？
4. **pgvector 选型理由？** 当前沿用 PostgreSQL 管理资料、向量与事务。已有 HNSW 索引，但离线实验是精确余弦，不是 HNSW 性能实验。追问：近似检索为何要与精确结果对照？

### 解析、切块与检索

5. **切块依据？** 标题、段落、句子边界与重叠；无标点长文本有字符保底。当前单位是字符，不是 token。追问：中英文、表格和代码共用字符阈值有什么问题？
6. **引用如何回原文？** 保存文档、块、页码、章节和字符范围，来源携带定位字段。旧文档需重新入库。追问：清洗/OCR 如何改变偏移？
7. **相似度为什么不等于有答案？** 主题接近的段落可能没有答案，专有编号也可能难被语义表征区分。追问：怎样构造困难负例？
8. **召回与重排分工？** 召回控制候选覆盖，交叉编码器对候选打分；重排无法找回未召回的证据，阈值过严还会误删。追问：候选 K 与最终上下文 K 为何分开？
9. **BM25/RRF 做了吗？** 尚未实现。可以讨论词项匹配和语义检索互补，但必须明确是后续实验。追问：中文分词、型号编号与不同分数量纲怎么处理？
10. **何时改写？** 知识库筛选无结果后最多改写重试一次，相同/空改写直接结束。追问：改写丢失专有词或改变意图怎么办？

### 实验与指标

11. **Recall、MRR、nDCG 区别？** 分别看证据覆盖、第一条相关结果位置、整体排序；本工具是二元块级标签。追问：一问多证据只命中一段是否够生成完整答案？
12. **无答案问题怎么评？** 单独统计空检索率，不混入可回答问题的 Recall 分母。零块不等于模型可靠拒答。追问：如何分别评检索拒答和生成拒答？
13. **实际结果？** 固定保留集24个可回答、6个无答案问题上，纯向量 Recall@4=1.0000，重排后=0.9167；无答案空检索率从0到1.0000。是小合成语料、改造前代码的一次检索实验，不能称生产准确率。证据：evaluation/reports/baseline-v1。
14. **如何防调参污染？** 同一资料的改写问题归同一划分，只用 dev 选方案，固定后看 test。反复看过的 test 需换新未知集。追问：如何消融并记录模型/切块/参数版本？
15. **首字快代表性能好吗？** 不代表。需分理解、检索、重排、首 token、总耗时和吞吐。已有 trace，尚无真实负载 SLA。追问：同步调用占用工作线程会怎样？

### 编排与可靠性

16. **为何统一 ChatService？** 普通与流式共享理解、路由、证据策略与引用收尾，减少规则漂移；依赖注入用于失败复现。追问：何时需要图框架、检查点和可恢复任务？
17. **联网开关如何保证？** 确定性路由统一决定 needs_web，实际调用只在该分支。不能仅信模型输出。追问：低置信度、无知识库、混合问题如何组合？
18. **资料不足怎么办？** 对需要依据的路径明确说明限制，不调用生成器补造业务事实；混合路径缺一方时提示范围。追问：相关片段其实没有答案，还需什么判定？
19. **编号校验能解决幻觉吗？** 只能清理不存在的编号，不能证明某句话被资料支持。追问：逐句支持性标注、人工复核和受控模型评审如何结合？
20. **如何防提示注入？** 目前采用独立 system 规则与 JSON 数据边界，不能宣称完全防御；需进一步结合权限和攻击样例。追问：为什么检索内容不能决定工具权限？

### 会话、流与工程

21. **问答为什么一个事务？** 两次独立写入可能留下半个问答；现在第二次失败时整对回滚。追问：断线重发如何通过请求幂等键避免重复？此功能尚未实现。
22. **旧记忆如何失效？** 写入事务内捕获历史/摘要指纹，模型在锁外运行，开始前和写回时核对；编辑/删除/新消息令旧任务放弃。追问：为什么最后消息 ID 检测不出编辑？
23. **停止流要做什么？** 前端取消并忽略旧回调，后端关闭上游；未完成流不作为成功保存。同步调用仍可能等超时。追问：为何 generator.close 单测不能替代 HTTP 断开验证？
24. **能否称企业生产系统？** 已有账号与知识库权限、持久入库队列、租约恢复、真实 PostgreSQL 并发和跨用户接口验证。尚未完成真实业务负载压测、高可用部署及完整依赖锁定，不能据此声称企业规模生产验证。可描述为“具备权限隔离、可恢复入库和事务一致性的 RAG 应用”。

## 简历建议

- 完善基于 FastAPI、Vue 3、BGE-M3 与 pgvector 的资料问答系统，支持多格式解析、重排、有限查询改写及可定位引用。
- 统一普通与 SSE 问答编排，增加资料不足与部分来源故障处理、阶段耗时追踪；采用事务问答写入与快照条件更新处理历史编辑后的记忆失效。
- 建立60条合成问题的固定检索评测，区分召回、排序与无答案空检索指标，记录模型/源码/语料指纹并分析重排取舍。

按真实参与和理解程度调整动词。没有真实负载与用户数据，不写“数万用户”“高并发生产落地”或泛化的准确率提升。

本轮落地改造可增加：

- 基于 PostgreSQL `FOR UPDATE SKIP LOCKED` 实现持久入库队列，结合租约续期、领取令牌和事务内分块替换，实现可恢复执行与幂等提交。
- 实现服务端登录会话、CSRF 防护、知识库成员权限与会话所有权，权限过滤贯穿向量 SQL 检索、SSE、原件下载和任务重试。
- 使用真实 PostgreSQL 独立连接验证会话原子写入、Worker 抢占和过期任务恢复，并完成本地 BGE-M3 入库检索冒烟。

面试追问应能讲清：为何至少一次执行仍需幂等提交；为什么租约过期后旧 Worker 必须被令牌隔离；为什么“未选库”必须在 SQL 层限定权限；为什么消息事务锁不能跨模型调用持有。证据与未验证边界见《落地验证记录》。

## 10 天练习（每天约一小时）

| 天 | 动手任务 | 自测产物 |
|---|---|---|
| 1 | 画入库与问答流程 | 不看稿讲90秒 |

| 3 | 看召回与重排函数 | 解释漏召回与阈值误杀 |
| 4 | 手算三个排名样例 | 算对Recall/MRR/nDCG |
| 5 | 读真实失败样例 | 解释重排为何未全面提升 |
| 6 | 跟踪四条路由 | 画出有限状态转换 |
| 7 | 跟踪SSE断开与保存 | 解释done/error的时机 |
| 8 | 阅读记忆竞态测试 | 复述“先编辑、后执行”问题 |
| 9 | 演示跨用户拒绝访问及 Worker 恢复 | 解释租约、令牌隔离与幂等提交 |
| 10 | 30分钟模拟追问 | 删掉简历中过强表述 |

每题自评：只会名词0分；能讲机制1分；能定位代码并举失败反例2分；能设计验证并说明边界3分。目标是高频问题达到2～3分。
