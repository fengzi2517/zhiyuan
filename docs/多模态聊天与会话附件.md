## 本地升级

在项目根目录停止旧 API 和 Worker 后执行以下命令。迁移版本从 1 升到 2，新增附件表和消息 JSON 字段，不删除已有资料、用户或聊天记录。

```powershell
.\.venv\Scripts\python.exe -m app.migrate
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

另开终端启动 Worker；它交替检查文档和附件队列，避免其中一类任务持续占用调度。

```powershell
.\.venv\Scripts\python.exe -m app.worker
```

前端开发启动方式不变：进入 `frontend` 执行 `npm run dev`，浏览器刷新。API 与前端使用相同 hostname。新增模块使用已有依赖，无新增 pip/npm 包。

## 模型配置

默认 SenseNova 6.8 支持视觉；快速模式传 `reasoning_effort=none`，深度模式省略该参数，使用供应商默认思考行为。辅助分类、改写、记忆与附件摘要仍使用原来的 `LLM_*` 配置；建议保留 `LLM_REASONING_EFFORT=none`，避免辅助步骤增加推理等待。

可以在 `.env` 用一行 JSON 配置 `CHAT_MODEL_PROFILES`，下例为默认模型的完整配置：

```dotenv
CHAT_MODEL_PROFILES=[{"id":"default","name":"SenseNova","model":"sensenova-6.8-flash-lite","vision":true,"fast_options":{"reasoning_effort":"none"},"deep_options":{},"context_chars":24000,"max_images":5}]
```

多模型时在数组里添加对象。可指定 `base_url` 和 `api_key_env`（密钥所在环境变量名），省略时复用 `LLM_BASE_URL` 与 `LLM_API_KEY`。这些配置不会下发前端。模式参数可用 `extra_body` 适配供应商支持的开关，但必须依据该供应商实际 API 配置；应用不会根据模型名称猜测未知供应商的能力。

省略 `deep_options` 会禁用深度开关；`vision:false` 会禁用看图。空 `fast_options` 显示“供应商默认”，不声称关闭推理。`context_chars` 是应用的文本字符预算（不是供应商 token 数），须给系统提示、输出和图片预留空间；默认 24000。`max_tokens` 或 `max_completion_tokens` 可放在模式选项中覆盖输出预算，最大 32768，两者不能同时填写。修改配置后重启 API 和 Worker。

## 使用和边界

- 支持选择、拖拽 TXT/MD/PDF/DOCX/PNG/JPEG/WEBP/BMP，粘贴图片；每轮最多 5 个文件、每个 20 MB、合计 50 MB。只发附件时默认请求概述内容。
- 原件与处理任务持久保存。卡片显示排队、解析、重试等待、就绪或失败；失败可从原件重试。发送前必须全部选中附件就绪。未发送消息的附件会话也会出现在侧栏，刷新后可恢复。
- 图片有视觉能力且开关开启时，发送规范化 JPEG 的 base64 内容；关闭时仅使用 OCR 文字。OCR 没有文字会阻止文字模式发送，提示启用视觉或移除附件。不会在视觉请求失败时偷偷改走 OCR。
- 图片先检查真实格式和 2500 万像素限制，再按方向规范化、透明背景合成白色、最长边缩放到 2048。原件保留。PDF 始终走文本层/扫描页 OCR；DOCX 提取段落和表格。复杂图表请附截图使用视觉模式。
- 短文档全文进入上下文；长文档问题按当前附件范围做向量检索。全文总结最多 19.2 万字符、16 个分组，遍历所有组并分层压缩，记录覆盖组数；总摘要预算 90 秒、20 次调用，每次至多 20 秒。超限或压缩失败明确报错，不把部分检索结果冒充全文总结。摘要会压缩细节，引用可打开原文核对。
- 解析上限为 PDF 300 页、提取文字 100 万字符；扫描页渲染受像素/边长限制；DOCX 受解压大小、成员数及压缩比限制。超过限制应拆分或重新导出。
- 附件仅当前会话可见，后续追问可选择该会话附件。删除会话取消任务并撤销访问，旧 Worker 的租约令牌不能恢复已删除资源。尚未发送的附件在 24 小时后由 `python -m app.operations cleanup --apply` 清理；该命令需由运维定期执行，默认不带 `--apply` 为预览。
- “保存到知识库”显示目标库与共享范围，需要编辑权限；同一附件到同一库幂等。副本进入现有入库队列，生命周期独立于会话。移除附件不会删除已保存的知识库副本。

## 接口与实现

`GET /models` 返回登录用户可选的模型能力。`POST /chat` 与 `/chat/stream` 新增 `model_id`、`thinking_mode`（fast/deep）、`vision_enabled`、`attachment_ids`。

`/sessions/{session_id}/attachments` 支持上传和列表；其下 `/{id}/original`、`/{id}/content`、`/{id}/retry`、`/{id}/save-to-kb` 与 DELETE 都校验用户和当前会话归属。问答生成前及持久化时再次检查访问权限。

附件任务与文档任务共用文件校验/存储、解析/OCR/切块/向量化组件，以及 `queue_lease` 的时钟、令牌、续租判断。各自存储任务资源，避免把私有附件伪装成共享知识库。附件提交、移除和会话删除统一按会话锁再任务行锁排序；成功问答在同一事务标记附件已使用并保存消息。
