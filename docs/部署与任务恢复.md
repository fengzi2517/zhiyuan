# 部署、鉴权与任务恢复

## 本地启动

保留原 `.env` 的模型服务配置，不要覆盖已有密钥。PostgreSQL 必须安装 pgvector。

```powershell
docker compose up -d postgres
.venv\Scripts\python -m app.migrate
.venv\Scripts\python -m app.admin bootstrap admin
.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

另一个终端启动 `.venv\Scripts\python -m app.worker`，前端使用 `cd frontend; npm run dev -- --host localhost --port 5173 --strictPort`。浏览器打开 localhost:5173，默认 API 自动使用同一 hostname 的 8000 端口。不要混用 localhost 和 127.0.0.1；Cookie 依赖同站点。

bootstrap 交互输入至少 12 字符密码，不存在默认密码。已有管理员时使用 `python -m app.admin create-user NAME [--admin]`，或登录后的账号管理页。管理员身份负责账号管理；资料仍需知识库成员权限。普通用户可创建自己的库。

所有修改请求需要 Origin 位于 TRUSTED_ORIGINS 和 X-CSRF-Token，登录只校验 Origin。前端自动传递 Cookie 与 CSRF。API 调用者先 POST /auth/login，保存 Set-Cookie 与响应 csrf_token。CSRF token 不存 localStorage。登录失败按账号和连接来源分别限流，窗口默认 15 分钟、最多 5 次失败；不会信任客户端伪造的 X-Forwarded-For。

## 旧数据迁移

先备份数据库及 uploads，再运行：

```powershell
python -m app.migrate
python -m app.admin adopt-legacy admin
python -m app.admin adopt-legacy admin --apply
python -m app.operations resume-legacy
python -m app.operations resume-legacy --apply
```

无 `--apply` 只展示清单。未认领知识库和会话默认不可见；迁移给指定管理员。无库文档归入新建的 Legacy import 库。原进程内任务若还留有原件，resume-legacy 创建持久任务；缺少原件会提示 reupload_required，需重新上传。已完成文档不重复向量化。

迁移使用 PostgreSQL advisory lock 串行执行，加列和建表步骤可重复执行；记录 schema_versions。DDL 可能已经执行一部分后失败，修复原因后重跑迁移；不宣称跨多连接 DDL 全部回滚。Web 与 Worker 只校验版本，不在每次启动时改表。

## 部署

`docker-compose.deploy.yml` 提供独立项目 rag-deploy 的 PostgreSQL、一次性迁移、Web 和 Worker，以及原件和模型共享卷。它创建自己的数据卷；不会自动搬迁本地开发库。已有数据须先备份恢复再执行迁移。

1. `.env` 设置随机 POSTGRES_PASSWORD；DEPLOY_DATABASE_URL 设置 `postgresql+psycopg://rag:<URL编码密码>@postgres:5432/rag`；TRUSTED_ORIGINS 设置正式 HTTPS 前端来源。
2. `docker compose -f docker-compose.deploy.yml up -d --build`。
3. `docker compose -f docker-compose.deploy.yml exec web python -m app.admin bootstrap admin`。
4. 构建前端前设置 `VITE_API_BASE_URL=https://你的API域名`，执行 `npm run build`。由 HTTPS 反向代理托管 frontend/dist，并转发 API 至本机 8000；建议同源，API 路径优先于 SPA 回退。
5. 反向代理必须关闭 SSE 缓冲，允许长连接，上传请求体上限至少覆盖 20 MB 文件和 multipart 开销；生产 Cookie 强制 Secure，因此必须 HTTPS。

首次模型加载需要模型下载，确保共享模型卷有足够空间。可运行 `docker compose -f docker-compose.deploy.yml exec worker python -c "from app.embeddings import embed_texts; print(len(embed_texts(['模型准备'])[0]))"` 预热。配置 HF_HUB_OFFLINE=1 前先确认模型缓存完整。Worker 的模型工作不持有领取任务的事务锁。

本轮提供部署配置；是否已构建镜像及调用真实模型，以实施记录为准。requirements 仍延续项目已有版本策略，正式部署应根据实际构建环境锁定依赖并保存镜像版本。

## 队列语义与故障演示

上传返回 HTTP 202 表示原件、文档和任务已持久化，文档随后经过 queued → running → succeeded（文档显示 done）。暂时性错误进入 retry_wait；超过次数或不可解析文件进入 failed。界面「重新入库」复用原件，无需重新选择文件。

任务使用 `FOR UPDATE SKIP LOCKED` 领取，租约默认 120 秒，每三分之一周期续租。Worker 崩溃后其他 Worker 领取过期任务，新 token 隔离旧执行者。成功提交在同一事务替换 chunks、保存全文及状态。执行语义是至少一次、提交幂等；模型计算可能重复，不承诺恰好执行一次。

演示步骤：上传一份资料，在 Worker 执行时停止该进程；Web 可继续查看 running 状态。等待租约过期并启动新 Worker，任务恢复，attempts 增加。完成后引用可打开原件。可同时启动两个 Worker 演示抢占。强制终止可能中断模型加载，建议使用测试库演示。

`GET /health/live` 检查进程；`GET /health/ready` 检查数据库版本和连接；登录后 `GET /jobs/summary` 查看有权限库的任务计数与过期执行数。日志包含请求 ID、用户 ID、任务 ID、Worker ID、尝试次数和状态转换；异常详情仅留服务日志。HTTP 请求耗时记录到响应头返回时，不代表完整流式生成耗时。

删除知识库取消其任务并删除文档和向量，原件在宽限期后由 `python -m app.operations cleanup` 预览，`--apply` 执行清理。默认宽限 24 小时，保留数据库仍引用的文件；清理也移除过期登录及限流记录。推荐低峰期运行，先查看 dry-run 输出。

## 备份与恢复

暂停上传和 Worker，使用 pg_dump 自定义格式备份数据库，同时备份 uploads 卷；两者要属于同一个停写窗口，模型卷可按需重建。保留加密备份和受控访问权限。

恢复到空 PostgreSQL+pgvector 库，使用 pg_restore 导入，恢复 uploads 至原配置位置，再执行迁移。storage_path 当前保存绝对路径；若从 Windows 迁到容器，必须在停写期间把每个文档路径映射到 `/data/uploads/<doc_id>/source<扩展名>`，校验实际文件后更新，不能直接沿用 Windows 路径。

恢复后先校验 /health/ready、登录、原件下载，再启动 Worker；未完成任务按租约恢复。不要对业务库执行测试的 TRUNCATE，也不要使用 compose down -v 清理业务部署。

## 定向集成验证

```powershell
docker compose -f compose.integration.yml up -d --wait
$env:TEST_DATABASE_URL='postgresql+psycopg://rag_test:isolated_test_only@127.0.0.1:5445/rag_test_foundations'
.venv\Scripts\python -m pytest integration_tests -q --basetemp=.test-tmp-integration
```

测试只接受 `rag_test_` 前缀数据库，并会清空该测试库中应用表。不要将业务库改名来绕过检查。与默认禁止网络的 tests/ 单元测试隔离。真实数据库测试采用确定性模型替身验证事务与权限，不能据此声称真实模型效果或生产吞吐量。

本地真实模型冒烟：管理员登录 → 创建库 → 上传含独特短语的 TXT → 启动 Worker 等待 done → 在指定库关闭联网提问 → 打开引用确认原文。需要本地 embedding 缓存及可用 LLM；此步骤的外部服务成本和结果单独记录。

## 权限变更边界

reader 只能查看和检索，editor 还可上传和重试，owner 可管理成员和删除库。会话只对创建者可见。无可读知识库不会回退到全库。回答完成前再次校验会话、登录和检索范围；权限撤销后拒绝保存。已经发送的 token 无法撤回，用户已保存的资料副本也无法远程回收。
