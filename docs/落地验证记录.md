# 落地能力验证记录 · 2026-09-12

本次在 codex/production-foundations 分支实现，基于 bd7b623。真实数据库使用独立 `rag_test_foundations`，PostgreSQL 18 + pgvector，监听 127.0.0.1:5445；未修改既有业务数据库、未使用另一个项目的 PostgreSQL 容器。

## 实现与证据

| 能力 | 本次验证 |
| --- | --- |
| 会话事务一致性 | 独立数据库连接并发保存，用户/助手消息不交叉；不同会话互不阻塞；助手保存失败回滚用户消息；旧记忆不能覆盖新历史或复活已删除会话 |
| 持久队列 | 双 Worker 只有一次有效领取；SKIP LOCKED 可跳过被占用任务；模拟租约过期可恢复；旧 token 不可续租/完成/失败新任务；重复提交无重复 chunks；次数耗尽终止；删除库阻止晚到提交 |
| 并发权限操作 | 并发授权上传不死锁；并发管理员停用至少保留一个有效管理员 |
| HTTP 权限 | 跨用户知识库、文档、原件、分块、向量视图、任务、消息和会话拒绝访问；只读成员不可上传/删除；空授权集合不回退全库；真实 SQL 检索只返回授权数据 |
| 登录与 SSE | Cookie HttpOnly、CSRF、令牌摘要保存、限流与退出撤销；正常 SSE 保存成对消息；生成期间撤销登录后无 done、无消息落库 |
| 实际模型入库 | 离线加载本机缓存 BGE-M3，TXT 经真实 worker.run_one 解析/切块/向量化写入 PostgreSQL，并成功检索回对应文档 |
| 迁移与维护 | 显式旧数据 dry-run/apply；清理 dry-run 不删文件，apply 保留仍被引用的原件；旧任务恢复幂等；错误日志不含测试正文 |

测试按新增及受影响路径分批执行，修复失败后只重跑失败或后续改动覆盖的用例，没有重复全量评测。

- 受影响 Python 用例：36 项最终通过（第一批 34 通过、2 个旧测试因鉴权/路由结构变化失败，适配后 2 项通过）。其中包括 8 项身份测试和 4 项队列单元测试。
- 新增维护测试：3 项通过；指定管理员接管旧数据的用例在变更后另行通过。
- 真实 PostgreSQL：10 项并发/队列测试、7 项 HTTP/权限测试、1 项真实模型冒烟，均已通过。
- 前端 SSE 与轮询：6 项通过；最终前端构建通过。
- 部署 Compose 与集成 Compose 配置语法校验通过；Git diff 空白检查通过。

独立静态审查发现并修复：删除库残留成员关系会阻止后续默认范围问答；Worker SQL 异常可能包含正文参数。分别通过删除回归和日志脱敏用例验证。后续收尾复核由主实现者完成。

## 可复现实验入口

普通集成测试：按《部署与任务恢复》设置 TEST_DATABASE_URL 后运行 `python -m pytest integration_tests -q --basetemp=.test-tmp-integration`。模型冒烟默认跳过，显式设置 `RUN_MODEL_SMOKE=1` 和正确 HF_HOME 后运行 `python -m pytest integration_tests/test_worker_smoke.py -q --basetemp=.test-tmp-model`。

本轮手动启动的隔离容器名称为 `rag-foundations-test`。若复现时选择 compose.integration.yml，需要先停止该容器以释放 5445 端口；不要同时启动两个相同端口的实例。该容器仅存测试数据。

## 未验证与边界

- 未构建完整生产 Docker 镜像、未执行正式部署或业务库迁移。部署配置语法通过不等于生产部署通过。
- 未新增外部 LLM 或 Tavily 实调用；真实模型冒烟覆盖本地 embedding 与数据库检索，SSE 使用确定性生成替身。
- 租约恢复通过真实数据库中的过期状态和多个调用者验证，没有把它描述成整机断电恢复实验。
- 未做吞吐压测、正式用户负载或高可用切换；不能写“支撑数万用户”或生产准确率。
- 前端保留原有大 bundle 提示；测试依赖存在 Starlette/AnyIO 弃用提示，均未导致本轮失败。没有声称完成浏览器视觉走查。
- 密码与角色配置由部署者初始化；旧资料默认隐藏，必须显式接管。依赖尚未全量锁定，现有检索基线也没有因这次工程改造重新测量。
