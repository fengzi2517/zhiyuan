# 编排与会话工作流

本轮在既有 FastAPI + ChatService 上完善状态、异常分支和会话生命周期，保留 direct / kb / web / hybrid 四条路由。

## 执行流程

~~~mermaid
flowchart TD
  A[问题与会话上下文] --> B[结构化理解与保守降级]
  B --> C[确定性路由]
  C --> D[知识库召回与精排]
  C --> E[按开关联网]
  C --> F[普通问题直接回答]
  D --> G{命中资料}
  G -->|否且尚未改写| H[改写一次并重检索]
  H --> I[证据检查]
  G -->|是| I
  E --> I
  I -->|资料不足| J[明确说明限制]
  I -->|有依据| K[带资料与限制生成]
  F --> L[统一引用校验]
  J --> L
  K --> L
  L --> M[同事务保存问答与记忆任务快照]
  M --> N[返回完成事件]
  M --> O[锁外生成摘要]
  O --> P{历史与记忆仍一致}
  P -->|是| Q[条件写回摘要]
  P -->|否| R[丢弃过期结果]
~~~

普通和流式问答共用阶段执行器，区别是普通生成或 token 流。状态包括理解、检索、精排、改写、联网与生成。trace 记录耗时和结果，run_id 关联日志；这些是可观察运行过程，不是模型内部思维链。

## 异常分支

| 场景 | 行为 |
|---|---|
| 问候后带实质问题 | 按知识问题理解，避免“你好，请解释…”跳过资料 |
| 根据资料写总结 | 按资料任务处理，不能仅因“写”字进入普通创作 |
| 知识库零命中 | 至多改写一次；仍无依据则明确说明资料不足 |
| 普通问题且未选库、没有资料 | 可直接回答，不声称查过资料 |
| 时效问题但联网关闭 | 明确无法核验最新信息 |
| 混合请求的一方来源异常 | 保留另一方来源，提示缺失范围 |
| 重排异常 | 保留向量排序并在 trace 标记降级 |
| 生成失败或空输出 | 结构化 error，无 done，不保存半段为完整答复 |
| 问答保存失败 | 事务回滚，返回 persistence_failed，不发送成功 done |

生成器使用独立 system 规则，任务、记忆、历史和资料用 JSON 表达；无来源回答也清理虚构编号。编号检查只证明编号存在，不能证明引用支持对应事实；相关但无答案的片段仍需要更强的事实核验。

## 会话与记忆一致性

save_exchange 把用户消息和助手消息放在一次事务里。第二条写入失败时第一条也回滚。

启用记忆时，在同一写入事务里取得历史/现有摘要指纹，交给后台任务。模型生成摘要发生在锁外。任务开始前与写回时分别核对指纹：用户编辑、删除会话、新消息或另一份摘要更新都会令旧任务失效。PostgreSQL 的写入路径使用会话对应的事务级 advisory lock；哈希碰撞只会造成额外串行。

编辑任意历史使长期摘要失效；编辑助手文本还清理该条旧引用和追踪。系统不会自动重生成后续回答；历史仍需用户核对。

没有新增数据库列。run_id、warnings 与 answer_mode 保存在 trace 的 outcome 项，读历史时还原。

## 边界

- 后续落地改造已补真实 PostgreSQL 的并发写入、事务回滚、过期记忆校验和队列竞争测试；这属于正确性验证，不是吞吐压力测试。鉴权、持久队列与部署参见《部署与任务恢复》。
- 记忆快照扫描该会话全部消息，长会话需改为持久修订号；并发下可能跳过过期摘要任务，不保证每轮都有摘要。
- 同步外部调用可能等待上游超时，关闭客户端连接不等于远端模型立刻停止计算。
- 入库仍是 API 进程内后台任务，独立 worker、租约、重试和断点恢复尚未实现。
- 认证授权、多人租户隔离、BM25/RRF、答案事实一致性评估仍是后续工作。
