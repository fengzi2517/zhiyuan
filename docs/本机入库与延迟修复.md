# 本机入库与闲聊延迟修复 · 2026-09-12

## 已确认的现象

用户报告 PDF/图片任务失败，日志仅含 ValueError；闲聊生成阶段约 59.9 秒，理解和路由仅毫秒级。

只读检查确认：PDF 原件可解析为 7 页、72 块，最大 500 字符；图片 OCR 可生成 438 字符的一个分块。两种文件的抽样向量化成功。原始那次 ValueError 在本轮正常权限下没有单独复现，不能断言是文件损坏、内存不足或某个库版本缺陷。

发现并修正的确定性问题：

- Worker 将所有阶段的 ValueError 都视为不可重试的文件错误，模型加载/向量化错误因此被错误归类。
- 日志没有阶段、切块进度或安全调用位置，无法定位失败点。
- 向量化沿用模型默认批量，PDF 多分块时峰值资源较高；现在显式小批量执行，默认 4，模型初始化加锁。
- LLM 未显式指定推理行为；当前服务默认响应包含 reasoning。相同简短问候的实测，默认约 7.17 秒、设置 reasoning_effort=none 后约 2.04 秒。该参数已通过当前服务实调用验证。
- 非流式调用同时存在 SDK 重试和手动 10/20 秒等待；现在统一由明确配置控制重试，默认 0。没有证据证明用户原来的流式 59.9 秒包含重试，不能把这段延迟全部归因于重试。

## 改动

解析、切块、向量化、提交分别记录耗时；向量化输出 `progress=4/72` 等批次进度。错误记录阶段、类型、文件名/函数/行号，不记录异常正文、文档或密钥。可确认的解析/无文本错误终止，模型或数据库阶段失败进入有界重试。前端任务错误摘要显示失败阶段。

当前 SenseNova 6.8 模型默认 `reasoning_effort=none`，未知供应商默认不发送该参数。流式输出继续只展示答案内容。LLM 日志区分第一个事件、首个答案 token 和总耗时；处理过程增加首字耗时。

```dotenv
LLM_REASONING_EFFORT=none
LLM_MAX_TOKENS=4096
LLM_MAX_RETRIES=0
LLM_TIMEOUT_SECONDS=60
EMBEDDING_BATCH_SIZE=4
```

新默认直接生效，不必覆盖现有 .env。需要恢复供应商默认推理行为时，在 .env 显式写 `LLM_REASONING_EFFORT=`；其他供应商应按其支持的参数配置。输出上限可按长回答需要调整。HTTP 超时是连接/读写等待限制，不是严格整段回答墙钟上限。

## 实际恢复结果

检查时没有活跃 Worker，这批 running 任务租约均已过期。通过现有领取/失败重试流程恢复，不强制改写有效租约。

| 文档 ID | 类型 | 最终状态 | 实际分块数 |
| --- | --- | --- | --- |
| 22 | PDF | done | 72 |
| 23 | PNG | done | 1 |
| 24 | TXT | done | 1 |

PDF 全量向量化约 41.99 秒，提交约 0.20 秒；图片解析/OCR 约 4.10 秒，含首次模型加载的向量化约 3.11 秒。这是本机一次运行的记录，不是吞吐承诺。

修复后现场对比：直接调用总耗时约 3.42 秒，项目闲聊编排约 4.03 秒；首字分别约 2.90 和 3.55 秒。该对比使用两个简短问候，回答长度不同，属于初步量级验证。新增脚本使用相同问候进行后续可复现比较。

随后执行新脚本，以完全相同的“你好”作对比：直接调用总耗时 9.139 秒、首字 8.632 秒；应用编排总耗时 9.716 秒、首字 9.247 秒。两次对比均处于同一数量级，但服务时延明显波动，不能承诺每次固定 4 秒，也不能把串行请求的耗时差精确解释为应用开销。

`python scripts/benchmark_chat_latency.py --runs 1` 会真实调用配置的 LLM，只发送问候且只打印耗时。它比较 LLM 与 ChatService，不包含浏览器、鉴权和反向代理耗时。模型服务负载、回答长度和上下文都会使结果波动。

## 验证与生效

新增运行时回归和日志安全测试 6 项通过，受影响编排/API/队列测试 17 项通过，前端构建通过；原件全量入库和数据库最终状态已验证。没有重复跑无关检索评测。

停止旧后端/Worker 后，分别在两个项目根目录终端启动：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

```powershell
.\.venv\Scripts\python.exe -m app.worker
```

前端 Vite 开发服务器一般会自动加载组件变更，刷新页面即可。已完成的这三个文件无需重新上传。
